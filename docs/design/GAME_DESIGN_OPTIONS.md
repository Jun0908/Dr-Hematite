# GAME DESIGN — ポイント、内政、危機、発明のゲーム性

> 最新の比較は [地図を主画面にするゲーム性の3案](GAMEPLAY_THREE_OPTIONS.md)。本資料は個別の経済・イベント・勝利条件の候補を保存する。共通DP、ターン制、研究ロードマップ中心の画面を採用済みとは扱わない。

本ファイルは決定仕様でなく「検討の材料」。作品の魅力は**科学が必要だから学ぶ**循環にある。

2026-11-14のユーザー訂正を反映した [GAME_CONCEPT](GAME_CONCEPT.md) は、大きな研究ロードマップとランダムな出来事を中心に置く。最初の砂嵐を導入にし、情報を段階的に見せる案を検討中。ポイント経済、作業能力、時間の進行方式は未決定で、本ファイルの各モデルを引き続き比較する。

## A. ゲーム形式の探索

| 形式 | 何が面白いか | 科学の役割 | 発展の見え方 |
|---|---|---|---|
| 文明発展＋危機対応 | 未来への投資と目前の危機を天秤にかける | 技術解放、効率化、代替手段 | 施設と基地レベルが上がる |
| サバイバル | 残り備蓄と故障の時間制限 | 化学で生存期限を延ばす | 資源枯渇→生産→循環 |
| 化学プラント | 反応・材料・装置をつなぐ楽しさ | 物質収支／反応条件 | 手作業→自動生産 |
| ローグライク | 事故・初期条件によって毎回変わる | 技術順序や代替レシピ | プレイごとに異なる文明 |
| 探査・科学発見 | NASA地図を頼りに有望地を探す | 地質／元素分析／不確実性 | 地図の意味が変わる |
| 競争・協力 | 限られた資源をめぐる戦略 | 技術優位・資源交換 | 複数の成長方針 |

一例として「ターン制の内政＋科学系統樹＋ランダム事故」は説明書なしの操作と緊張感を共存させやすいが、現時点で方式を確定しない。

## B. ポイント経済：検討すべき3モデル

### モデル1：共通開発ポイント（DP）
- 基地・研究室・工作室・生活環境によって毎ターンDPを得る。
- DPを探索／研究／建設／修理などに使う。
- 必要素材と電力は別リソースとして要求。DPだけで化学反応・建設が起こるわけではない。
- ポイントを貯めて次の高度技術に投資するか、目前の故障へ使うかがドラマとなる。

### モデル2：研究知識と作業能力を分離
- `研究/知識ポイント`は実験・分析・観測で獲得。
- `作業能力`は宇宙飛行士・ロボット・工作室が毎ターン生産。
- 実際の製造には水・鉱物・電力・時間が必要。
- 発見と製造の価値を分けられるが、UIの見せ方に工夫がいる。

### モデル3：行動枠主体
- 毎ターン2〜4個の行動を選び、研究設備・ローバー・自動化で選択肢が増える。
- 材料と電力が制約で、ポイントは技術解放の進捗を示す。
- 「次の1手」を直感的にしやすい。

### 例示の初期値（すべて仮）

| パラメータ | 仮案 |
|---|---|
| 1ターン | 1 sol（火星の一日） |
| 基本DP | +3/ターン |
| 研究室稼働 | +2 DP/ターン、電力を消費 |
| 工作室稼働 | +1 DP/ターン、電力を消費 |
| 生命維持安定ボーナス | +1 DP/ターン（設計案） |
| 探索コスト | 2 DP＋電力 |
| 技術研究 | 5〜7 DP＋前提発見 |
| 修理・建設 | 3〜4 DP＋材料＋電力 |

現実の宇宙開発にDPは存在しない。ゲーム進行のための指標。

## C. 内政の成長：増えるものと増えるリスク

- **発電所**：装置を増やせるが、部品・日照・保守が必要。
- **研究室**：分析・技術研究が速まるが、電力を使う。
- **工房・3Dプリンタ**：修理速度と製造選択肢が増えるが、材料消費がある。
- **水採取場・浄水場**：水の収支が改善するが、ローバー・熱・フィルターが必要。
- **酸素プラント**：酸素不足を緩和するが、電力の競合が増す。
- **栽培室**：食料自給率が上がるが、水・養分・照明・温度に依存する。
- **遮蔽・緊急シェルター**：放射線イベントに強くなるが、資材と作業時間を使う。

人口・生存率・文明レベル・自給率・研究効率などのどれを「都市成長」の基準にするかは今後検討。

## D. ランダム事故の種類

| イベント | 直接の危機 | 事前対策・選択肢 | 学べること |
|---|---|---|---|
| ダストストーム | 太陽光発電量低下 | 蓄電、電力優先順位、予備電源 | 発電・電力需要 |
| 酸素製造故障 | O₂生産停止 | 予備パーツ、酸素備蓄、代替ルート | 電気化学・冗長性 |
| 水再生系故障 | 回収率低下 | フィルター、現地採水、消費抑制 | 分離・水処理 |
| 太陽高エネルギー粒子イベント | 船外作業・被ばくリスク | 早期警報、避難、遮蔽 | 放射線・安全管理 |
| 地下氷の予測外れ | 採掘効率低下 | 地中探査・再試掘・代替地点 | 不確実性・科学的検証 |
| 温室の環境異常 | 栽培収穫量低下 | 光、水、温度、栄養の調整 | 光合成・植物生理 |
| 樹脂フィラメント不足 | 部品印刷不可 | リサイクル・回収部品 | 高分子と再利用 |
| 低温・設備凍結 | 配管／熱損失問題 | 断熱・ヒーター・予備電源 | 状態変化・熱 |

全事故を完全な純ランダムにせず、予兆・リスク表示・対策技術・複数の回避手段を検討。事故が「研究した技術を試す場」になる。

## E. 1ターンの流れの例

1. 生命維持設備の消費と生産を確認。
2. 発電・生産・開発ポイントの増減を表示。
3. ローバー探索／技術研究／修理／建設／運転設定の行動を選択。
4. 発明によってマップ上の資源の新しい使い道が判明。
5. ターン終了。環境・イベント・施設が変化する。
6. なぜ成功/失敗したかを短い科学メモで示す。

最初の数ターンは操作を自発的に発見できるレベルまで情報を段階表示する。

## F. 仮の勝利条件

- **生存**：備蓄の限界までに酸素と水の安定供給を実現。
- **科学**：特定の技術系統樹を完成し、装置を動かす。
- **文明**：生命維持・電力・放射線防護・食料の複数指標で基地を発展させる。
- **危機克服**：一定数の予測できないイベントを科学で突破。
- **スコア/周回**：同じ期間でどれだけ自給率と文明度を伸ばせるか。

## G. 具体的なドラマ例

水が足りない→氷探索。氷が見つかる→加熱用の電力が足りない。電力を水の処理に使うと温室が止まる→レゴリスの断熱素材を研究。次に砂嵐が接近→バッテリーを増やすか酸素の生成を急ぐか。ライバルは必須ではなく、**自然条件と設備の制約が相手**になる。

## H. 48時間で検討可能なスケール（目安であって強制しない）

小規模マップ、少数設備、約8〜15技術、3〜6種類のイベント、10〜20分の1プレイ、直感的な研究・探索・修理UI。4 Agentは必要な状況になった時の補助戦力として考える。
