# UX & EDUCATION — 説明書なしで学びながら遊ぶ

現行の遊び方は [GAME_CONCEPT](GAME_CONCEPT.md) を参照。以下の初回操作案は、このコンセプトに合わせて更新した。

## 目指す体験

プレイヤーが教科書的な文章を読む前に「押す・動かす・混ぜる・作る・結果を見る」という直感的な操作から遊び始められる。学年や知識に応じて科学ノートを深掘りできる。

## 小出しに学ぶチュートリアル案

ユーザーから「一気にやると中学生・高校生が理解できないので、小出しに出す、チュートリアルなどもよい」と提案があった。大きな科学ロードマップは保ち、表示と案内を段階的に増やす。

最初のミッションは砂嵐への備えだけを扱う。例えば「発電が減る前に酸素を蓄えたい」という具体的な目的から、必要な資源・装置を調べ、工程を動かして結果を見る操作を案内する。初期装備や最初に研究する技術の選定は未決定。別の事故や全研究分野の説明を同時に詰め込まない。

| 段階 | 画面と操作の例 | 理解の焦点 |
|---|---|---|
| 一本の道筋 | 氷の調査・採取→融解・浄化→水。次に触る工程と不足条件を表示 | 資源を見つけ、工程を通して使えるものを作る |
| 一つの枝分かれ | 電気分解で酸素と水素ができる。まず当面の目的に関係する側を案内 | 一つの材料に複数の使い道がある |
| 系統間のつながり | 後で鉄の研究を開くと、以前の水素とつながる | 知っているものが、新しい発明に役立つ |
| 自分で進める研究 | 次の目標を選ぶ。新しい分野では必要になった操作だけ短く案内 | 自分の興味と出来事に合わせて研究の順序を考える |

全段階を砂嵐の前に終える必要はない。基本操作が分かったら自由な研究へ移り、鉄や樹脂などは進んだ時点で案内する。この順序は理解の例で、固定の研究順や必修コースではない。

## 情報を増やすときの設計案

- 一度の案内で新しく覚える判断を一つに絞り、まず操作と結果を体験する。数値、化学式、装置の詳細を同時に要求しない。
- 新しい素材を得たときや目標を選んだとき、その素材の用途や必要工程を広げる。枝の出現に理由を持たせる。
- 一歩先の魅力的な発明を絵で予告する。全体や遠い目標は興味があれば自分で開ける。表示の都合で科学的な依存関係を変えない。
- 理解済みの工程はまとめて表示し、いつでも再展開する。短い説明は再表示できる。
- 最初は「何が何に変わるか」、詳細を開くと反応式・エネルギー・装置条件・出典。年齢だけで内容を固定せず、本人が深さを選べる。
- 導入中の時間の扱いやヒント量は検討する。説明を読む間に危機が進みすぎる設計を避ける。

## 画面のつながり

主画面は火星の地図。資源候補、ローバー、基地設備とその変化を見て、次にすることを選ぶ。発明ノートのロードマップは別ページで開き、研究のつながりと将来を見渡す。具体的なゲーム性は [3案の比較](GAMEPLAY_THREE_OPTIONS.md)を参照。

NASA地図から得た資源候補は研究につながり、発明は基地の設備や生活を変える。ストーリーボードで出来事と選択の結果を伝え、必要に応じて関係する地図上の設備や研究ページへ移る。研究ページ内では全体・目標までの道筋・一工程を切り替える。細かな配置は未決定。

## 研究ツリーに動画を入れる案

ユーザーの追加提案を受け、火星版Polytopiaという有力案で、別ページの研究ツリーに説明動画を組み込む。具体化した内容は [ゲーム性の比較資料](GAMEPLAY_THREE_OPTIONS.md)を参照。

技術を選ぶと、まず得られる能力・必要な素材と装置・ゲーム内での使い道を表示し、短い動画を任意で再生できる。動画は「入力→変化→出力→用途」を描く。例えば電気分解なら、水・電力・装置から酸素と水素ができ、それぞれをどこで使えるかが分かる。

字幕と静止図で見直せるようにし、詳しい反応式と出典はさらに開ける。視聴完了やクイズの正解を通常の技術解放条件にはしない案。ゲーム内で必要な情報は視聴しなくても確認できる。視聴中に危機が進みすぎない時間設計を検討する。

検証するのは動画の再生数だけでなく、学んだ素材の用途を別の発明へ応用できるか。動画の制作・外部素材の選定・実装は未着手。

## 学年別の学び

| 学びの題材 | 小学生 | 中高生 |
|---|---|---|
| 水氷 | 氷を温めると水になる | 相変化、エネルギー、水処理 |
| 電気分解 | 水から酸素と水素ができる | 反応式、原子数、物質量・効率 |
| 鉄鉱物 | 赤い石は鉄の原料になりうる | 酸化還元・化学量論・採鉱工程 |
| プラスチック | 熱で形を変える樹脂 | 熱可塑性、高分子、劣化、PHB |
| 栽培 | 水・光・栄養が必要 | 光合成、資源循環、制御 |
| 電力 | 同時に全部動かせない | kWh収支・需要管理・冗長性 |
| 放射線 | 避難所が必要 | 放射線量、遮蔽、確率と防護 |

## 教育が本当に成立したかの検証例

- ゲーム前に「酸素を作る方法は？」など1〜3問の簡易質問。
- プレイ中は技術の根拠を見せる。クイズの正答を無理にゲートにしない案もある。
- プレイ後に「なぜ太陽光発電が減ると酸素製造が止まる？」「なぜ鉱物分布は掘れば必ず取れる場所を意味しない？」と問いかける。
- 自力で最初の工程を動かせたか、次に必要なものを見つけられたか、迷った時間を観察。
- 枝が増えたとき「前に作ったものがここにも使える」と説明できるか、次に作りたいものがあるかを確かめる。
- 案内が長く感じられないか、案内後に自分で研究を選べるか、初期画面が簡素でも将来の広がりを感じられるかを確かめる。
- テスト実施前に学習効果を実証済みと表現しない。

## 提出向けUXストーリー

**一つの資源→発明→別の用途の発見→系統がつながる→基地が育つ**という広がりを見せる。砂嵐やランダムな出来事が、その研究を使う目的と選択を生む。短い紹介でも、一本道の課題の奥に大きなロードマップがあることを伝える。
