# 基地・領土・資源・加工：現行ルールと次の案

更新：2026-11-14。ユーザーの「基地を占領すると周囲の資源も移る仕組みと、素材加工をどう両立させるか」に対する設計整理。**現行コードで確認した事実と、未実装の提案を分ける。以下の提案はユーザーの確定仕様ではない。**

その後のユーザー提案「設備は本拠地の別画面、地図は資源争奪と戦闘、中継Podを重視」を受けた最新の比較・推奨は [本拠地＋Pod案](HQ_POD_GAMEPLAY.md)。本書の複数基地ごとの設備・電力管理は、比較する前案として保持する。

## 1. 次の版を説明する三つのルール案

1. **基地を持つと、その囲いの土地と設備を使える。** 原料は現地調査と採取設備によって得る。
2. **原料は装置で加工して初めて役立つ。** 設置後は自動運転し、研究・材料・電力の組み合わせで文明が育つ。
3. **基地を奪うと、その囲いと設備がまとめて移る。** 既に相手の共有備蓄へ入った物資や研究は奪わない。

「地下にある資源」「採取済みの物資」「生産する設備」をこの三つのルールで区別する。画面では土地の色、備蓄アイコン、装置の絵に対応させる。

## 2. 現在と次の案の比較

現行の根拠は [game.js](../../game/game.js) の `ownsArea`、`capture`、`attack`、`production`、`siegeCheck`。一般向けの現行説明は [RULES](../../game/RULES.md)。

| 対象 | 現行コードの動作 | 次の版への提案 |
|---|---|---|
| 土地 | 自軍基地から2マス以内、または補給中継所から1マス以内なら建設可能。両軍の建設範囲が重なる場合もあり、土地ごとの唯一の所有者・所属基地はない | 各マスを一つの基地の領域へ割り当てる。領域は境界線で示し、所属基地をタップで確認できる |
| 中立拠点 | 工作クローラーが隣接して費用を払い、前哨基地を作る | 中立の開拓基地を確保すると、その領域もまとめて獲得する |
| 資源候補 | ローバーで調査し、自軍の建設範囲内に採取場を置く | 調査と採取場の条件は維持。領域を得ただけでは原料は増えない |
| 設備 | 採取場も電解装置も地図の各マスに置く。設備は陣営を記録するが所属基地を持たない | 採取場は地図、加工装置は基地の拡大画面へ置く。すべて一つの基地に所属させ、地図と拡大画面は同じ設備を表示する |
| 物資 | 陣営に一つの共有在庫。設備がそこから材料を取り、生成物を戻す | 当面維持。基地間の物資配送は自動で、個別倉庫・運搬量の操作は導入しない |
| 電力 | 初期発電・太陽電池・蓄電を陣営全体で集計 | 基地ごとに発電・需要・蓄電を管理。その基地の採取場と装置に供給する。画面では一つの電力計として示す |
| 加工 | 材料と電力があれば毎ラウンド自動生産。主に在庫差分と停止理由で確認する | 自動生産を維持し、原料→装置→生成物の流れを基地内で見せる。停止時は不足物資か電力の場所を強調する |
| 敵基地 | 攻撃で耐久0にすると制圧扱い。中枢基地は一定期間後に勝敗判定。敵前哨基地や設備の所有権が移る処理はない | 敵の開拓基地も占領可能にする。領域、採取場、発電・加工設備が一括移管され、中枢基地の占領完了で勝利する |
| 工場への輸送 | 物資輸送路や到達性を生産条件にしていない。機体の補給・通信は別の仕組みとして存在 | 次の版でも工場の物流は自動の抽象化にする。既存の機体補給・通信と、工場への物資配送を混同させない |

現在の前哨基地の耐久を0にしても、Polytopia風の領土・設備移管は起きない。これは現行の未実装部分として扱う。

## 3. 領域と基地の扱い

- 最初の試作は現在の規模を基に、両軍の中枢基地と少数の中立開拓基地を置く。領域は盤面作成時に一意に割り当て、資源の初動が両軍で成立するように配置を調整する。
- 領域は基地の持ち主に従う。重複所有をなくし、基地を奪っても境界の形は変えず色だけを切り替える。最初の版では人口による境界拡張を入れない。
- 中立基地の領域でも調査・移動はできるが、採取設備の建設には基地の確保が必要。発見と所有を分ける。
- 敵が資源マスを通っただけでは所有権は移らない。資源を継続して使う権利は所属基地の占領で得る。採取場単独の占領・略奪は最初の版に加えない。
- 山の登坂研究、資源の調査、必要な技術・材料は、領域を得た後も必要。領域の色だけで山が通れたり未調査の氷を採れたりしない。
- 中継設備は機体の補給・通信を助ける。領域を新たに所有する機能は基地へまとめる。

ここで領土の仕組みを簡潔にし、深さは「どの資源圏を取るか」「どんな加工能力を育てるか」「どの基地を守るか」へ置く。

## 4. 占領で何が起こるか

提案する流れは、**基地の防備を崩す → 地上機が基地マスへ入る → 相手の1回の操作機会を越えて保持する → 占領完了**。中立基地は防備を崩す工程を省く。相手の操作機会は両陣営で同数とし、現在のラウンド番号だけによる判定へ依存させない。

- 占領中は対象基地と所属設備の生産・基地からの補給を停止する。以前の所有者は反撃で占領機を排除し、防備を修復できる。占領機が破壊・撤退した場合は占領が中断し、所有権は元の側に残る。防備の修復だけで敵の占領機を消す扱いにはしない。
- 占領完了時に、基地、領域、採取場、加工装置、発電・蓄電設備をまとめて移管する。設備の故障・強化状態は保持し、奪い合いで修理や新品化が起きないようにする。地元の蓄電残量は基地の状態として引き継ぐ。
- 占領した設備は、引き継いだ調査済み採取場も含め、材料と現地電力が足りれば次の生産処理から使える。移管時の即時生産や、同じラウンドに両軍が一つの設備の生産を得ることはない。
- **共有備蓄、開発力、研究、機体は移管しない。** 科学的な資源候補が消えるのではなく、今後そこから採取できる陣営が変わる。
- 既存設備の運転には自陣が未取得の研究でも利用を認める案を採る。新設・増設・強化には自陣の研究が必要。基地を奪っても技術ツリーが丸ごと解放されることはない。
- 未開発の資源候補に関する相手の調査情報は一括取得しない。稼働中の採取場については施設の記録として採取に必要な情報を引き継ぐ。
- 中枢基地の占領完了なら勝利。開拓基地なら対戦を続ける。全体の生命維持不足による敗北は当面現行を引き継ぐが、基地を一つ失った直後に立て直す余地があるか試遊する。

一例：氷採取場と採水装置のある基地を失うと、以後の氷と水の生産が減る。共有備蓄にある水まで一瞬で消えないため、奪回・別の採取場・節水や循環の発明へ切り替える時間が残る。奪った側も電力不足なら直ちに全設備を動かせるわけではない。

## 5. 基地の生産をシンプルに見せる

地図では基地の境界と、主要な生産物のアイコンを見せる。原料と加工後の物資は別のアイコンにし、「氷がある」だけで水や酸素が生まれると誤解させない。

基地を開くと、装置のイラストと次の流れを表示する。

```text
地図の氷採取場 → 氷 → 融解・浄水装置 → 水
                                       ├→ 温室 → 食料
                                       └→ 電解装置 → 酸素 ＋ 水素
```

物資は陣営の共有備蓄に出入りする。他基地から使う入力には「共有備蓄から」、出力には「共有備蓄へ」を示す。基地にない採取場や加工装置を、地元で動いているように描かない。物資の自動融通はゲーム上の抽象化で、電力は基地ごとの供給能力として扱う。

- 通常は必要な装置だけを表示する。装置をタップすると「入力・電力・出力」、さらに知りたい場合に科学の説明や原画を開く。
- 研究で設計図を得て、開発力・部品などで設備を設置する。完成後は毎ターン自動稼働。材料や電力の不足時にだけ介入を促す。
- 資源の種類を内部で一つにまとめない。初期は水・酸素・食料と電力を中心に見せ、水素や金属などは関連する発明で登場させる。
- 配管や毎ターンの材料投入は自動。初期の操作は「装置を設置・増強する」「不足時の優先先を選ぶ」に絞る。装置の増設可能数・基地拡張費は試遊用の仮値で調整する。
- 生産は全基地に同じ手順を適用し、先に処理した陣営や基地だけが得をしない。次の実装時に、入力・出力を処理する工程順、生命維持の予約、同一工程の競合優先順を定義し、予測表示と共有する。循環系統を同じ処理中に無限に回さない。

科学の前提・持ち込み装備・ゲーム上の簡略化は [SCIENCE_ROADMAP](../science/SCIENCE_ROADMAP.md) に従う。ゲームの在庫単位を分子数や実機の生産量と同一視しない。

## 6. 次に試す実装範囲

1. 土地と設備に所属基地を与え、地図で境界を見せる。現在の重なる建設範囲を置き換える。
2. 開拓基地の占領・停止・奪回・移管を実装し、領域と全設備が同時に移ることを確認する。
3. 一つの基地の拡大画面で、氷→水→酸素・水素の生産を動かす。地図と基地画面で設備・費用・生産を二重計上しない。
4. 基地単位の電力計と、共有備蓄への入出力を表示する。占領前に「何を得て、相手が何を失うか」を確認できるようにする。
5. AIにも同じルールを使い、両開始位置で資源確保→加工→開拓基地の争奪→中枢攻略まで試遊する。

個別倉庫、手動輸送、物流の遮断、細かな配管、人口による領土拡張は、この検証に含めない。前回の基地案で挙げた輸送経路は、まず自動配送として扱う。

確認したいのは「どの基地を奪えばどの生産が変わるかを地図で予測できる」「生産停止の理由を基地画面で説明できる」「基地を失っても備蓄で対応を選べる」「基地管理のために毎ターン全画面を巡回しなくてよい」の四点。費用・稼働停止期間・基地配置・既存設備の利用価値が一方的な勝ちを生まないかは未検証。
